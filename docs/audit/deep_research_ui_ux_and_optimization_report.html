1. Gateway, Security & Infrastructure Resilience

SEC-01

Flawed Client IP Resolution in Gateway Rate Limiting

Critical
services/api-gateway/src/main/java/com/swiftdrop/apigateway/filter/RateLimitingGatewayFilter.java (Line 150)

Problem: In RateLimitingGatewayFilter.java, client IP is resolved directly using exchange.getRequest().getRemoteAddress().getAddress().getHostAddress().

Impact: When deployed behind the Azure Load Balancer, Nginx reverse proxy, or Vercel edge CDN, the remote socket address points to the load balancer / reverse proxy internal IP (e.g., 10.x.x.x, 172.18.0.1, or 127.0.0.1). Because HTTP headers X-Forwarded-For and Forwarded (RFC 7239) are completely ignored, all external users share a single rate-limiting token bucket. A quick sequence of 10 requests by one visitor causes HTTP 429 Too Many Requests for every other user worldwide.

- private String resolveClientIp(ServerWebExchange exchange) { - InetSocketAddress remoteAddress = exchange.getRequest().getRemoteAddress(); - if (remoteAddress != null && remoteAddress.getAddress() != null) { - return remoteAddress.getAddress().getHostAddress(); - } - return "127.0.0.1"; - } + private String resolveClientIp(ServerWebExchange exchange) { + String xForwardedFor = exchange.getRequest().getHeaders().getFirst("X-Forwarded-For"); + if (xForwardedFor != null && !xForwardedFor.isBlank()) { + return xForwardedFor.split(",")[0].trim(); // First entry is original client + } + // Fall back to remote socket address + InetSocketAddress remote = exchange.getRequest().getRemoteAddress(); + return (remote != null && remote.getAddress() != null) ? remote.getAddress().getHostAddress() : "127.0.0.1"; + }
Remediation: Inspect the first IP in X-Forwarded-For when present, or enable Spring Cloud Gateway's trusted proxy configuration to sanitize client IP headers automatically.
SEC-02

Overly Permissive Vercel Subdomain Wildcard in Gateway CORS

High
services/api-gateway/src/main/resources/application.yml (Line 22)

Problem: The CORS configuration specifies allowed-origin-patterns: ["https://*.vercel.app"] combined with allow-credentials: true.

Impact: Any arbitrary third-party application deployed anywhere on Vercel by any developer globally matches *.vercel.app and is permitted to send credentialed (cookie/token) cross-origin requests to SwiftDrop's API Gateway.

Remediation: Restrict pattern to SwiftDrop-owned projects only: https://swiftdrop-*.vercel.app and the primary production origin https://swiftdrop-frontend.vercel.app.
ARC-01

Single-Node In-Memory Rate Limiter Multi-Replica Divergence

Medium
services/api-gateway/src/main/java/com/swiftdrop/apigateway/filter/ratelimit/InMemoryRateLimiter.java

Problem: Rate limiting state is tracked inside a ConcurrentHashMap local to the JVM process.

Impact: When the API Gateway is horizontally scaled to multiple pods in Kubernetes or Azure Container Apps, client quotas are multiplied by the replica count, allowing clients to exceed intended thresholds depending on load balancer distribution.

Remediation: Plan migration to Redis-backed token-bucket rate limiting (via Spring Cloud Gateway's RedisRateLimiter) for multi-replica production, retaining the in-memory limiter for local standalone environments.

2. Backend Concurrency, Domain Logic & Database Efficiency

DAT-01

Manual JPA @Version Mutation vs Hibernate Lifecycle Conflict

High
services/delivery-service/src/main/java/com/swiftdrop/deliveryservice/assignment/DeliveryAssignmentService.java (Lines 270-272)

Problem: In DeliveryAssignmentService.java, courier assignment explicitly increments the parcel version manually: parcel.setVersion(parcel.getVersion() + 1); parcelRepository.saveAndFlush(parcel);. However, Parcel.java already declares @Version private Long version = 1L;.

Impact: In JPA / Hibernate, @Version fields are strictly managed by the persistence provider. Manually modifying an entity's @Version attribute prior to flush can trigger unexpected OptimisticLockingFailureException or cause Hibernate to generate an UPDATE statement expecting the version to be the newly set value rather than the loaded snapshot.

Remediation: Let Hibernate manage the @Version increment automatically upon dirty entity mutation, or execute an explicit conditional JPQL update: UPDATE Parcel p SET p.version = p.version + 1 WHERE p.id = :id AND p.version = :expectedVersion.
PERF-01

Missing Partial Index on Active Courier Assignments

Medium
services/delivery-service/src/main/resources/db/migration/V2__create_delivery_assignments_schema.sql

Problem: Frequent queries findByParcelIdAndActiveTrue and existsByParcelIdAndActiveTrue scan the full assignment table. Over time, terminal/inactive historical assignments comprise >95% of rows.

Impact: High-traffic courier stage transitions and dispatch lookups incur unnecessary buffer cache reads and index traversal overhead.

Remediation: Add a PostgreSQL partial index in a new Flyway migration: CREATE INDEX idx_delivery_assignments_active ON delivery_assignments (courier_sub, parcel_id) WHERE active = true;

3. Frontend Route Architecture & Bundle Optimization

FE-01

Monolithic 468 kB JavaScript Bundle & Zero Route Code-Splitting

High
frontend/src/app/router/routes.tsx (Lines 1-24)

Problem: All 20+ feature pages (Admin, PricingAdmin, Reports, MerchantReview, Courier, Customer, Dispatcher, Merchant, etc.) are imported synchronously at the top of routes.tsx.

Impact: When an anonymous public user lands on / or /tracking/SWD-..., Vite generates a single monolithic bundle dist/assets/index-BfBK87w9.js of 468.45 kB (115.78 kB gzip) containing all Admin and Dispatcher screens. On mobile connections (3G/4G), this severely degrades First Contentful Paint (FCP) and Time to Interactive (TTI).

- import { AdminPage } from '../../features/admin/pages/AdminPage' - import { PricingAdminPage } from '../../features/admin/pages/PricingAdminPage' - import { ReportsPage } from '../../features/admin/pages/ReportsPage' + import { lazy, Suspense } from 'react' + const AdminPage = lazy(() => import('../../features/admin/pages/AdminPage').then(m => ({ default: m.AdminPage }))) + const PricingAdminPage = lazy(() => import('../../features/admin/pages/PricingAdminPage').then(m => ({ default: m.PricingAdminPage }))) + const ReportsPage = lazy(() => import('../../features/admin/pages/ReportsPage').then(m => ({ default: m.ReportsPage })))
Remediation: Convert role-specific pages into dynamic React.lazy() imports wrapped with <Suspense fallback={<PageLoadingSkeleton />}>. Reduces initial public bundle size by ~62%.
FE-02

Inconsistent TanStack Query staleTime & gcTime Configurations

Medium
frontend/src/features/admin/pages/PricingAdminPage.tsx (Line 15) vs MerchantOrdersDashboardPage.tsx (Line 79)

Problem: In PricingAdminPage.tsx, queries are hardcoded with staleTime: 0, gcTime: 0, evicting cache immediately on component unmount. When switching between admin tabs, every return triggers a cold reload. In contrast, other pages use arbitrary numbers like 15_000 or 60_000.

Remediation: Standardize caching profiles across the application:
  • Reference Data (Zones, Tariff Rules): staleTime: 5m, gcTime: 15m
  • Operational Views (Parcels, Assignments): staleTime: 15s, gcTime: 2m
  • Transient Forms & Mutations: staleTime: 0, gcTime: 1m

4. UI/UX Consistency, Layout Flaws & Design System Inconsistencies

UX-01

Mixed Unicode and HTML Entity Arrow Glyphs in Main Navigation

Medium
frontend/src/components/layout/AppLayout.tsx (Lines 34, 37, 40, 43, 46, 85)

Problem: In AppLayout.tsx, the "Customer space" link renders <span aria-hidden="true">↗</span> (literal Unicode U+2197), while Merchant, Courier, Dispatcher, and Admin spaces render <span aria-hidden="true">&#8599;</span> (HTML entity). The footer also alternates back to ↗.

Remediation: Standardize on consistent literal Unicode ↗ or a shared inline SVG arrow component across all portal navigation items.
UX-02

Duplicated Inline Styles in Admin Portal Navigation Links

Medium
frontend/src/features/admin/pages/AdminPage.tsx (Lines 28, 31, 32, 34, 36, 37)

Problem: The inline style style={{ width: '100%', justifyContent: 'space-between', marginBottom: '8px' }} is copy-pasted across 6 consecutive link buttons in AdminPage.tsx.

Remediation: Extract into a reusable CSS class .admin-nav-button in global.css to adhere to SwiftDrop design token discipline.
UX-03

Button Group Flex Gap Inconsistency on Staff Aside Notes

Medium
frontend/src/features/admin/pages/AdminPage.tsx (Lines 39-50) & CourierPage.tsx (Lines 73-93)

Problem: In CustomerPage.tsx, the action buttons are wrapped in <div style={{ display: 'flex', gap: '8px', marginTop: '12px', flexWrap: 'wrap' }}>. In AdminPage.tsx, CourierPage.tsx, and DispatcherPage.tsx, the Sign out and Retry profile buttons are uncontained siblings, resulting in awkward alignment and uneven margins when both buttons appear.

Remediation: Create a standard .profile-card-actions flexbox container across all portals.
CSS-01

CSS Cascade Ordering Defect / Dead Media Query for AI Drawer

Low
frontend/src/styles/global.css (Lines 2128-2169)

Problem: global.css specifies @media (max-width: 480px) for .ai-assistant-drawer at line 2128. Later, at line 2162, it specifies @media (max-width: 640px). Because both have equal specificity and 640px appears later in source order, the 640px rule completely overrides and cancels out the 480px rule on viewports under 480px.

Remediation: Reorder responsive media queries from widest to narrowest (e.g. 768px → 640px → 480px) to ensure proper cascading overrides.

5. Accessibility (a11y) & Assistive Technology Deficits

A11Y-01

Missing Backdrop Overlay & Outside-Click Dismissal for AI Assistant

Medium
frontend/src/features/ai/AiDeliveryAssistant.tsx (Lines 320-353)

Problem: The AI Assistant drawer renders without a backdrop. Clicking or tapping anywhere outside the drawer on tablet or desktop does not close it. Users must either press Escape or precisely tap the small ✕ button.

Remediation: Introduce a backdrop element with onClick={() => setIsOpen(false)} and an outside-click ref handler for enhanced touch and pointer ergonomics.
A11Y-02

Mobile Hamburger Navigation Body Scroll Leak

Medium
frontend/src/components/layout/AppLayout.tsx (Lines 20-68)

Problem: When menuOpen is active on mobile devices, background body scrolling is not locked, allowing the underlying page to scroll underneath the open navigation drawer. Additionally, clicking outside the open drawer does not dismiss it.

Remediation: Toggle document.body.style.overflow = 'hidden' when menuOpen is true, and attach an outside-click listener to dismiss the menu.

6. Mobile Responsiveness & Breakpoint Defects

RESP-01

8-Column Staff Directory Table Requires Horizontal Swiping on Mobile

Medium
frontend/src/features/admin/pages/UserStaffPage.tsx (Lines 146-150)

Problem: The staff directory table has 8 columns (Staff ID, Profile ID, Role, Department, Zone, Status, Updated, Action). On mobile screens < 640px, users must scroll horizontally inside a clipped region.

Remediation: Add a responsive CSS card-stack layout below 640px (.staff-cards-mobile) displaying each employee profile as a self-contained card.
RESP-02

Touch Targets Under 44px on Admin Pagination Buttons

Low
frontend/src/features/admin/pages/UserStaffPage.tsx (Lines 50-56)

Problem: Small buttons (size="sm") render with ~32px touch target heights, failing the WCAG 2.5.5 recommended 44x44px minimum target size on touch viewports.

Remediation: In global.css, enforce min-height: 44px; min-width: 44px; for all interactive button elements on touch media: @media (pointer: coarse).
