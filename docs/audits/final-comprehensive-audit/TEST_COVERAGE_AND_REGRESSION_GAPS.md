## 2. Critical Test Coverage Gaps & Blindspots

Despite the impressive test count (3,314 passing tests), critical blindspots allowed multiple severe defects to escape into the primary integration branch `test`.

### 2.1 The Gateway Routing Test Gap (`QA-001`)
- **Blindspot:** In `services/api-gateway/src/test/java/com/swiftdrop/apigateway/config/GatewayRoutesConfigTest.java`, tests assert route mappings for `/api/v1/parcels/**`, `/api/v1/pricing/**`, and public tracking.
- **Escape:** The suite never included test cases verifying the route `/api/v1/staff/**` or `/api/v1/admin/pricing/**`. Because `GatewayRoutesConfigTest` had no negative assertions or exhaustive contract parity checks against `PROTOCOL_MATRIX.md`, the omission of `/api/v1/staff/**` (`BE-001`) was never caught in CI.
- **Remediation Requirement:** Add a parameterized test in `api-gateway` that loops through all 15 declared external REST endpoints and verifies that each path is matched by a route locator and forwarded to the designated microservice URI.

---

### 2.2 The Keycloak Token Tenant Claim Blindspot (`INT-005`)
- **Blindspot:** In `services/delivery-service`, integration tests for `MerchantParcelBookingController` (such as `MerchantParcelBookingControllerTest.java`) were written with mocks or mock JWTs that explicitly injected `"merchant_id": "m_test_123"`. Alternatively, tests used the M2M header `X-Merchant-Api-Key`.
- **Escape:** No integration test ever exercised the controller with an authentic Keycloak-generated JWT representing a standard merchant browser session. Consequently, the team never discovered that Keycloak issues tokens without a `merchant_id` claim, rendering merchant web bookings unusable in reality.
- **Remediation Requirement:** Create a contract integration test between `accounts-service`, Keycloak realm fixtures, and `delivery-service` verifying that a raw token generated by Keycloak for a merchant user can successfully book a parcel without requiring manual claim injection.

---

### 2.3 Mocked Frontend Tests Concealing Fake Implementations (`FE-001`, `FE-002`)
- **Blindspot:** In `frontend/src/features/merchant/`, tests for `BulkOrderUploadModal.test.tsx` verified that clicking "Import Orders" caused the modal to close and invoked `onImportComplete`. Because Mock Service Worker (MSW) or component tests asserted the callback rather than asserting an outgoing network request, the test suite passed even though the component used a `setTimeout` mock and made zero API calls.
- **Escape:** `FE-001` (fake CSV import) and `FE-002` (fake webhook test ping) passed 100% of frontend tests while being completely non-functional in a real production environment.
- **Remediation Requirement:** Update frontend tests to assert that `fetch` or React Query mutations are dispatched with the exact payload expected by the backend.

---

### 2.4 Offline Ingress Skipping in Python Suite (`QA-002`)
- **Blindspot:** In `tests/test_ingress.py`, 5 tests check Kubernetes Ingress routing. These tests check if port 80 is open; if connection is refused, the tests are unconditionally skipped with `@unittest.skip`.
- **Impact:** Developers running `python3 -m unittest discover -s tests` locally on macOS or Linux without a running k3d cluster skip all ingress verification, creating a false sense of comprehensive coverage.
- **Remediation Requirement:** Enable a fallback mode where ingress tests can target the local Spring Cloud Gateway on `localhost:8080` using a configuration flag `SWIFTDROP_GATEWAY_URL`.

## 3. Recommended Automated Test Gates for CI/CD

To prevent regressions, the following automated test gates should be enforced in `.github/workflows/ci.yml`:

1. **Route Parity Gate:** An automated script matching all endpoints in `docs/architecture/PROTOCOL_MATRIX.md` against `GatewayRoutesConfig.java`. Build fails if any path is unmapped.
2. **Contract Compatibility Gate:** Pact or Spring Cloud Contract verification between `delivery-service` and Keycloak user token schemas.
3. **No-Fake-Call Gate:** ESLint or custom AST linter rule in `frontend/` flagging any `setTimeout` used inside form submission handlers.
4. **Bundle Size Budget Gate:** Vite build fails if any single JavaScript chunk exceeds 500 kB without explicit chunk splitting approval.
