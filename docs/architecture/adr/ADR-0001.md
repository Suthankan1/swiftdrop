# ADR-0001: Independent business services and team monorepo

**Status:** Accepted as v1.3 target · **Baseline:** Devarom v1.3 · **Implementation verification:** not asserted by this documentation starter.

## Context

We need a maintainable, teachable, independently testable courier-delivery system with the assignment's security/integration and reporting requirements.

## Decision

Four separately buildable/deployable Spring Boot business services plus gateway and one GraphQL query API. A monorepo simplifies student coordination without merging runtimes. Each service owns its DB.

## Alternatives/trade-offs

Simpler monolith rejected by lecturer direction; separate repos increase team coordination overhead.

## Consequences / implementation checks

Use separate Spring Initializr projects in `services/`; no shared JPA entities or cross-service SQL.

**Revisit if:** human-approved architecture or assignment constraints change; record a replacement ADR and cross-team contract impacts.
